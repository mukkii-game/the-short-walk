# Short Walk — v0.1 プロトタイプ

死のロングウォークをパロったデスゲーム・リズムゲーム。
お手本が消えたあとも、頭の中の感覚だけで歩き続ける。

企画の全体像は [企画書.md](企画書.md) を参照。

---

## 遊ぶ

ビルド不要、外部ライブラリなし。ただし **実音源とスプライトを読み込むためサーバ経由で開いてください**
（`file://` だと合成音＋手描きシルエットに落ちます。ゲーム自体は動きます）。

```bash
python -m http.server 8123
```

### ルール

- **どのキーでも、画面のどこを触っても一歩。** ボタンは1つだけ
- ペースメーカー（旗持ち）が示すリズムとペースで歩く。提示の間は全員自動で歩く
- 号令 **3, 2, 1, START** でペースメーカーが消え、無音になる
- 無音の間、**規定位置から枠を超えて離れた者はその場で処理される**。ジャッジタイムは無い
- ズレは持ち越し。全10課題

タイトル画面で `Shift+C` を押すと入力遅延の測定（隠し機能）。

## デバッグ用クエリ

難易度カーブを人手で10周しなくても測れるようにしてある。

| クエリ | 意味 |
|--------|------|
| `?auto=30` | σ30ms の仮想プレイヤーが自動で全ラウンド歩く |
| `?bias=1.2` | 仮想プレイヤーの系統的テンポ誤差 1.2%（既定 0.8%） |
| `?round=6` | 第6課題から開始 |

例: `index.html?round=8&auto=26&bias=0.5` で終盤だけ自動確認。

ブラウザを開かずに採点モデルだけ回す検証スクリプトも用意してある:

```bash
node tools/balance.js
```

腕前ごとの平均生存ラウンドと完歩率を出す。難易度の数値をいじったら、まずこれを回すのが速い。
`node tools/profile.js` は各課題での指標（ドリフト／ブレ／一致率）の内訳を出す。

## 調整するときに触る場所

### 1. お題そのもの — `js/patterns.js`

```js
{ bpm: 108, bars: 2, demo: 4, echo: 2, black: 10, name: '崩れた拍子',
  pattern: [P(0), P(0.5), P(1), P(2), P(2.5), P(3.5),
            P(4), P(5), P(5.5), P(6), P(7), P(7.5)] }
```

`P(拍位置)`。1拍=1.0、1小節=4拍。`bars` は1フレーズが何小節ぶんか。
`black` が無音で歩き続ける小節数＝このゲームの中核なので、ここを削ると別のゲームになる。

### 2. 採点の重み — `js/judge.js` の `J.W`

```js
alpha: 0.030,  // ドリフト（系統的に速い/遅い）1msあたりの減点 … ゆるい
beta:  0.350,  // ブレ（刻みの不安定さ）1msあたりの減点     … 厳しい
gamma: 120.0   // 手足の取り違え 100%あたりの減点            … 最も厳しい
```

「少し速いが刻みは正確な人」が生き残り、「平均は合ってるがガタガタな人」が死ぬ配分。

### 3. 難易度カーブ — `js/world.js` の `W.NPC`

NPCの実力を「淘汰の梯子の何段目に相当するか(tier)」で直接定義している。

```js
s1: 0.080,     // tier1（第1ラウンドのボーダー）のNPCのブレ σ = 80ms
slope: 0.0055, // 1ラウンド進むごとに σ が 5.5ms 厳しくなる
```

`slope` を上げると終盤が急に難しくなり、下げると誰でも完歩できる。

現在の設定での実測（採点モデルのみのシミュレーション、各30試行）:

| プレイヤーの腕前 | 平均生存 | 完歩率 |
|---|---|---|
| 下手（σ60ms, テンポ誤差3%） | 2.9課題 | 0% |
| 普通（σ45ms, 1.8%） | 6.1課題 | 0% |
| 中の上（σ36ms, 1.2%） | 8.0課題 | 17% |
| 上手（σ29ms, 0.8%） | 9.3課題 | 53% |
| 達人（σ22ms, 0.4%） | 10.0課題 | 97% |

全10課題を完歩した場合のプレイ時間は約6分40秒。

### 4. 見た目 — `js/render.js` の `CFG` と `PAL`

キャラクターは **LPC素材を合成したドット絵スプライト**（`assets/sprites/crowd.png`）。
差し替えは `tools/build_sprites.py` を編集して再実行（要 Pillow）。
スプライトが読み込めない環境（`file://` 直開き）では手描きシルエットに自動で落ちる。
**LPC は CC-BY-SA 3.0。公開時はクレジット表記が必須**（[assets/sprites/CREDITS.md](assets/sprites/CREDITS.md)）。

歩行アニメはスプライトのコマ送りを**ゲームの一歩に従わせている**（素材のアニメ速度ではなく）。
押した瞬間に踏み込みの絵になる。この対応は `js/render.js` の `spriteFrame()`。


`ppm`（1mあたりのピクセル数）を上げると位置のズレが読み取りやすくなり、下げると群衆の圧が増す。
`PAL.roadFar` / `roadNear` は**人物より明るく保つこと**。暗くすると影絵が浮いて見えなくなる。

隊列の形は `js/world.js` の `W.LANES`（横に並ぶ人数＝道幅）、`W.RANK_GAP`（前後の間隔）、
`W.LANE_FAR` / `W.LANE_NEAR`（道の端）で決まる。
NPCの個性の配分は同ファイルの `TYPES`。

## 音

**メトロノームは存在しません。** 拍を刻む記号音は一切鳴らさず、リズムの手本は先導者の足音で示します。
左右は録音のテイクと音程で判別できるようにしてあります。

足音・風・汽笛・警告・ビーム・処理音は **実音源**（[効果音ラボ](https://soundeffect-lab.info/)の素材を加工）。
提示・追従フェーズの下敷きだけ、拍を持たない合成ドローンを敷いています。

出典は [assets/CREDITS.md](assets/CREDITS.md)、差し替え手順と加工ツールは
[assets/README.md](assets/README.md) にまとめてあります。

読み込めているかの確認:

```javascript
SW.audio.loaded()   // ブラウザのコンソールで実行
```

## マルチプレイ

「ミンナデ」からオンライン対戦（最大12人、1人でも可・空きはNPCが埋める）。
方式はラウンド単位のロックステップで、**ラウンド中は通信ゼロ**。
終わったら各自の最終ズレを1つ提出し、サーバが順位を切って全員に判決を配る。
リズム判定は各端末のローカル時計基準なので、回線や端末差でプレイ感覚は狂わない。

- ローカル検証: `cd server && npm install && node node-server.js`
- 本番: Cloudflare Workers に `npx wrangler deploy`（手順は [server/README.md](server/README.md)）。
  出てきたURLを `js/net.js` の `SERVER` に書くこと。**書くまで公開サイトの「ミンナデ」は動かない**
